# Norutoki

> **いつもの移動を、検索しない。**

Norutoki（ノルトキ）は、普段利用する「いつものバス移動」と時刻表を登録しておくことで、現在時刻から次に利用できる便をすぐ確認できるWebアプリケーションです。

毎日利用するほどではないため時刻までは覚えていない。しかし、何度も利用しているので毎回検索するのは面倒。

そんな「たまに使う、いつもの移動」を、検索せず確認できる体験を目指して開発しました。

---

## サービスURL

https://norutoki.onrender.com

※ RenderのFreeプランを利用しているため、一定時間アクセスがない場合はスリープ状態になり、初回表示に時間がかかることがあります。

---

## サービス概要

Norutokiでは、ユーザーが普段利用するバス移動を「いつもの移動」として登録できます。

例えば、

- 家の近く → 駅
- 駅 → 家

といった行き・帰りのルートと、それぞれの時刻表を一度登録しておきます。

次回からはNorutokiを開くだけで、現在時刻をもとに

- 次のバスの出発時刻
- 出発まであと何分か
- 本日の便が終了している場合は翌日の最初の便

を確認できます。

一般的な乗換案内のように「目的地までどう行くか」を検索するのではなく、

**すでに行き方を知っている「いつもの移動」で、次に乗れる便をすぐ確認する**

ことに特化しています。

## 開発背景

私は普段、月に数回ほど同じバスを利用します。

バス停の場所や目的地までの行き方は分かっていても、毎日利用するわけではないため、バス停の正式名称や出発時刻までは覚えていません。

そのためバスを利用するたびに、

1. バス停名を調べる
2. バス会社のWebサイトを開く
3. 該当する方面を探す
4. 一日分の時刻表を見る
5. 現在時刻以降の便を探す

という操作を繰り返していました。

しかし、本当に知りたい情報は、

**「いつもの場所から、次のバスが何時に来るか」**

だけです。

調べること自体を面倒に感じ、「このくらいの時間にバスがあったはず」と感覚でバス停へ向かい、結果として次の便まで長く待つこともありました。

そこで、

**一度登録した「いつもの移動」なら、次回から検索しなくていい**

という状態を作れないかと考え、Norutokiを開発しました。

---

## 解決したい課題

### Before

バスを利用するたびに、

**検索 → バス停を探す → 時刻表を開く → 現在時刻と比較する**

必要があります。

### After

Norutokiでは、

**アプリを開く → いつもの移動を見る → 次の便が分かる**

という少ない操作で確認できます。

Norutokiが提供したい価値は、単に時刻表を表示することではありません。

**「次のバスを調べる」から「Norutokiを開けば分かる」へ変えること**

を目指しています。

## 想定ユーザー

以下のような人を想定しています。

- 月に数回程度、同じバスを利用する人
- バス停の場所や行き方は分かっている人
- 利用頻度が低いため時刻までは覚えていない人
- 外出前や移動中にスマートフォンから次の便を確認したい人
- 毎回バス会社のサイトや検索エンジンで調べることを面倒に感じている人

特定の年代ではなく、**「毎日ではないが、同じ移動を繰り返す人」**を対象としています。

## 主な機能

### ユーザー機能

- ユーザー登録
- ログイン
- ログアウト
- マイページ

ユーザーごとに自分専用のルート・時刻表を管理します。

### いつもの移動の管理

普段利用する移動を登録できます。

登録できる主な情報は、

- ルート名
- 乗車場所
- 目的地
- 行き / 帰り
- メモ

です。

登録したルートは、

- 一覧表示
- 詳細表示
- 編集
- 削除

ができます。

### 行き・帰りの分類

ルートを「行き」「帰り」に分類できます。

例えば、

- 行き：家の近く → 駅
- 帰り：駅 → 家

として登録することで、往復の移動を管理できます。

### お気に入り

よく利用するルートをお気に入りとして登録できます。

### ルートの並び替え

登録した「いつもの移動」を、自分が使いやすい順番に並び替えられます。

### 曜日別時刻表

各ルートに対して、

- 平日
- 土曜日
- 日曜日・祝日

の時刻表を登録できます。

時刻表は後から編集することもできます。

※ 現在のMVPでは、日曜日を「日曜日・祝日」ダイヤとして扱っています。日本の祝日を外部カレンダー等から自動判定する機能は未実装です。

### 次の便の自動判定

現在時刻と登録された時刻表を比較して、現在時刻以降で最も近い便を表示します。

例えば現在時刻が `18:35` で、

```text
18:20
18:42
19:05
19:30
```

という時刻表の場合、

```text
次のバス 18:42
あと7分
```

のように確認できます。

### 本日の便終了後の翌日案内

その日の時刻表に、現在時刻以降の便が残っていない場合は、翌日の曜日区分に対応した時刻表から最初の便を案内します。

これにより、夜にアプリを開いた場合でも翌日の最初の便を確認できます。

## 基本的な使い方

### 1. ユーザー登録

アカウントを作成し、ログインします。

### 2. 「いつもの移動」を登録

例えば、

```text
家の近く → 駅
```

というルートを登録します。

### 3. 時刻表を登録

登録したルートに対して、

```text
平日
土曜日
日曜日・祝日
```

それぞれの出発時刻を登録します。

### 4. 次の便を確認

Norutokiを開くと、現在時刻をもとに登録したルートの次の便を確認できます。

### 5. 帰りのルートも登録

```text
駅 → 家
```

も登録しておけば、外出先から帰る際にも同じように次の便を確認できます。

## 設計上のポイント

### 次の便の取得処理

1つのルートに対する次便判定は `RouteDepartureFinder` に切り出しています。

現在の日付・時刻から曜日区分を判定し、その日の時刻表から次の便を取得します。

当日の時刻表が存在し、本日の便がすべて終了している場合は、翌日の曜日区分に対応する時刻表から最初の便を取得します。

### 複数ルートの次便取得

複数の「いつもの移動」に対する次便取得は `UserRouteDeparturesFinder` にまとめています。

Controllerにビジネスロジックを集中させず、次便取得の責務をService Objectへ分離しています。

### ルートの並び替え

並び替え処理は `UsualRoute` モデルの

```ruby
move_up!
move_down!
```

にまとめています。

positionの交換処理も共通化し、Controller側は処理を呼び出すだけの構成にしています。

### N+1対策

Bulletを導入し、主要画面のN+1問題を確認しています。

時刻表と出発時刻を利用する処理では、必要に応じて `includes` を使用して関連データを事前読み込みしています。

## 今後実装したい機能

MVPでは、まず

**「いつもの移動を登録しておけば、検索せず次の便を確認できる」**

という中心的な体験を完成させることを優先しました。

今後は以下の機能を検討しています。

- GTFS / GTFS-JPなど公共交通データとの連携
- 時刻表の写真を利用したOCR登録
- 日本の祝日を考慮したダイヤ判定
- 現在地に応じた行き・帰りルートの優先表示
- バス停までの徒歩時間を考慮した案内
- 出発時刻に合わせた通知
- リアルタイムの遅延・運休情報
- 地域ユーザーによるおすすめルート共有
- バス以外の「いつもの移動」への拡張

ただし、機能を増やすこと自体を目的にはせず、

**「次の便を確認するまでの手間を減らす」**

というNorutokiの中心的な考え方を維持しながら改善していきます。
